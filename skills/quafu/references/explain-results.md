# 解读结果、给普通人讲明白

## qf analyze 算了什么

| 量 | 含义 | 怎么讲 |
|---|---|---|
| 理想分布 | 本地模拟器（`scripts/qfsim.py`）精确算出的各结果概率 | 「如果量子计算机完美，结果应该是这样」 |
| 实测分布 | 计数 ÷ 实际纳入的次数（`shots_returned`） | 「真机上实际测到的」 |
| 落在理想结果上的比例 | 理想概率 ≥ 5% 的那些结果，实测合计占多少 | 「正确答案占了多少」 |
| 经典保真度 | (Σ √(p·q))²，两个分布的相似度，1 为完全一样 | 「和理想有多像，满分 1」 |
| 总变差距离 TVD | ½ Σ \|p − q\|，0 为完全一样 | 「至少有这么多比例的结果『跑偏』了」 |
| 统计起伏 | 约 1/(2√N)，N 是 shots | 1024 次测量本身就有约 ±1.6% 的随机起伏，小于这个的差别不说明问题 |
| 读出估计（只有真机） | 用当次校准数据里被测比特的「0 读对率」「1 读对率」，算出「只有读出误差时」正确答案还剩多少 | 实测和它差不多 → 主要是读出误差；明显更低 → 门误差和退相干也有份 |

特殊模板另有：`rotation` 拟合 P(1)=a−b·cosθ 得到「对比度」；`vqe-h2` 由 Z 基、X 基两组测量算出每个 θ 的能量 ⟨H⟩，再拟合 a+b·cosθ+c·sinθ 求最低点；`qaoa-maxcut` 算每组 (γ,β) 的平均割值和测到最优分法的概率。

需要别的指标时，读 `quafu-runs/<号>.json`（原始计数、实际执行的线路、物理比特映射）自己用 Python 算。

## 噪声的大白话

讲之前先说一句：**真机有噪声是正常的，现在全世界的量子计算机都这样**，这正是在真机上跑的意义——看到真实的物理。

- **读出误差**：测量那一下，把 0 看成 1 或把 1 看成 0。好比用一台偶尔眼花的秤。1 读错通常比 0 读错多，因为处在 1 的比特会自己慢慢掉回 0。
- **门误差**：每个操作都不是绝对精准，像用手转旋钮总有一点偏差。两个比特之间的操作（CNOT/CZ）比单个比特的操作差十倍左右，所以双比特门越多结果越差。
- **退相干**：比特的量子状态只能维持几十微秒（T1、T2），线路越长，越多信息「漏」到环境里。
- **统计起伏**：抛 1024 次硬币也不会正好 512 次正面。差别在 ±1.6% 以内时，别把它当噪声。
- **编译带来的额外操作**：平台会把逻辑线路翻译成真机能执行的操作，比特不相邻时还要插入交换操作，实际的门比写的多。

讲结果的顺序：算法想要什么 → 真机给了什么（用百分比）→ 差在哪、为什么 → 这说明了什么（比如「正确答案仍然是出现最多的那个，算法在真机上是成立的」）。

## 不要说的

- 不要把一次运行的小差别说成规律；不要说「量子优势」「比经典计算机快」——这些小例子在经典电脑上一瞬间就能算完，它们的价值是**演示原理**。
- 不要把模拟器结果说成真机结果。
- 不要用没解释的术语。
