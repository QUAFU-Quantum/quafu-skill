# 登录细节

QUAFU SDK 有两种身份：**网页登录**（个人电脑，90 天有效，到期重新授权，不续期）和 **API Key**（服务器、CI，不过期，直到在网站上停用）。两者能做的事一样：提交、查询、取消自己的任务。都不能改账号、不能管理 API Key——那些只能在网站上做。

## 网页登录是怎么完成的

`python -m quafu login` 启动后：

1. 在本机开一个只听 127.0.0.1 的临时端口，生成一个授权链接（PKCE，链接里不含任何秘密）；
2. 尝试用默认浏览器打开链接（WSL 里用 Windows 的默认浏览器）；
3. 用户在网页上登录、点「授权」后，浏览器跳回那个本机端口，SDK 换到令牌、存进 `~/.quafu-sdk/credentials.json`（目录 0700、文件 0600），命令结束并打印「已登录」。

在 agent 的命令行里（不是交互终端）运行时，SDK 只等浏览器跳回，不读键盘输入，所以放后台跑没问题；最长等 1 小时。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 命令一直不结束 | 用户还没在网页上点授权 | 提醒用户；`python -m quafu whoami` 查到账号就说明好了，可以结束后台命令 |
| 浏览器没打开 | 没有图形界面或默认浏览器 | 把输出里的链接发给用户，在**同一台电脑**上打开 |
| 授权后网页显示一串授权码 | 浏览器跳不回本机（远程机、容器） | 用户自己在终端运行 `python -m quafu login`，把授权码粘到那个终端（5 分钟内有效、只能用一次） |
| `LoginFailed` | 网页上点了拒绝、超时或授权码不对 | 重新运行 |
| `NotLoggedIn` | 没登录，且当前环境不能交互 | 按上面的方法登录；服务器上用 API Key |
| `LoginExpired` | 90 天到了 | `python -m quafu login --force` 重新授权 |
| `LoginRevoked` | 用户在网站「已登录设备」里撤销了，或 API Key 被停用 | 重新登录 / 换 Key |
| 网页提示游客不能授权 | 用的是游客身份 | 先在网站注册正式账号 |

## 当前用的是谁

`python -m quafu whoami` 显示账号、平台地址、凭证种类（`oauth` 即网页登录 / `api_key`）、来源（显式传入 / 环境变量 / 本机保存）和到期时间，凭证只显示掩码。取凭证的顺序：`Client(api_key=...)` > 环境变量 `QUAFU_API_KEY` > 本机保存的登录 > 都没有时发起网页登录。所以设了 `QUAFU_API_KEY` 时，本机的网页登录不生效。

## API Key（服务器、定时任务）

1. 用户在网站个人中心创建 API Key（`qf_` 开头，只显示一次）。
2. 由**用户自己**设环境变量：`export QUAFU_API_KEY=qf_...`（PowerShell：`$env:QUAFU_API_KEY = "qf_..."`）。不要让用户把 Key 发到对话里，你也不要把它写进脚本或文件。
3. 想存进本机：`echo "$KEY" | python -m quafu login --api-key -`（SDK 先向平台验证，过了才存）。

多人共用一个系统账号的机器（共享服务器、共享 Jupyter）上，别用网页登录——同一系统账号下的程序都能读到登录文件；用环境变量里的 API Key，用完在网站上停用。

## 退出

`python -m quafu logout`：网页登录会先在平台上撤销再删本机文件；API Key 只删本机副本，Key 本身要去网站停用。

## 平台地址

默认 `https://quafu.com.cn`，不用设置。连别的部署时用 `QUAFU_BASE_URL` 或 `--base-url`；登录态按平台地址分开存。SDK 默认**不走系统代理**，需要代理时设 `QUAFU_PROXY=host:port`。
